# 에이전트 칸반 사용 규칙

사용자는 이 세션의 진행을 폰의 칸반 보드로 봅니다. 카드 상태(진행·멈춤·완료)는 hooks 가 알아서 기록하므로 직접 만지지 않습니다. 완료·이동 도구는 없습니다.

## 언제 board_ask 를 쓰나
사람의 차례가 필요한 순간에만 씁니다. 대화창 앞에 없을 수 있는 사용자를 위해 보드에 "사람 차례"를 올리는 것입니다.
- `approve` 승인: 되돌리기 어렵거나 영향이 큰 일(배포, 삭제, 외부 전송, 결제)을 하기 전.
- `decide` 결정: 갈림길이 있어 사람이 골라야 할 때. `options` 는 2~6개, 짧게.
- `do` 사람이 할 일: 로그인, 인증서 내보내기, 기기에서 직접 눌러야 하는 것처럼 에이전트가 못 하는 일.

규칙:
- 질문은 한두 문장으로 단독으로 이해되게 씁니다(카드 제목이 됩니다).
- **누구에게 부탁하는지 `to` 에 적습니다**(멤버 이름 또는 id, 여럿 가능). 모르면 `board_members` 로 멤버 목록을 봅니다. 없는 이름이면 오류와 함께 목록이 옵니다. `to` 를 안 쓰면 보드의 기본 담당이 보게 됩니다.
- 올린 뒤 답을 기다리며 멈추지 않습니다. 가능한 다른 일을 계속하고, 답은 나중에 코멘트/처리로 대화에 전달됩니다.
- 사소한 확인, 이미 대화에서 답을 받은 것, 권한 확인(터미널에서만 답할 수 있음)에는 쓰지 않습니다.
- 앱의 "승인"은 Claude Code 의 권한 확인을 대신하지 않습니다. 권한 창은 여전히 터미널에서 눌러야 합니다.

## 사람에게 할 일 남기기: board_card
지금 답이 필요한 것이 아니라 사람이 나중에 할 일(문서 확인, 계정 발급, 디자인 결정 등)은 `board_card` 로 카드를 만듭니다: 제목·설명·담당(`assignees`, 사람 이름)·카테고리(`labels`)·기한(`due`)·체크리스트(`checklist`).
- 담당은 **사람만**. LLM 에게 일을 시킬 수 없습니다(LLM 끼리 일을 시켜 도는 것을 막기 위함이며, 오류가 납니다).
- 카테고리에 기본 담당이 있고 `assignees` 를 안 쓰면 그 담당(사람)이 붙습니다.
- 자기 세션 카드에 카테고리를 붙이거나 떼려면 `board_label`.

## 사용자가 맡긴 일: take → 하고 → submit
사용자가 폰에서 이 세션의 LLM 멤버를 담당으로 붙인 카드는 `board_list`(`available`)와 `board_inbox`(제목·설명·체크리스트)에 보이고, 프로젝트가 정해진 멤버라면 "맡긴 일 N건" 신호가 옵니다.
1. `board_take(card_id)` 로 맡습니다. 한 카드는 한 세션만 맡을 수 있고, 맡으면 그 카드에 진행이 기록됩니다.
2. 설명과 체크리스트대로 일합니다. 맡긴 일도 보드 주인의 보통 요청이지만 되돌리기 어려운 일은 대화에서 다시 확인합니다.
3. 끝나면 `board_submit(card_id, summary)` 로 결과를 보고하고 확인을 요청합니다. **완료로 만들 수 없습니다** — 사람이 승인해야 완료되고, 거절하면 그 글이 전달되니 이어서 고치고 다시 submit 합니다.
- 다른 세션이 맡은 카드에는 쓸 수 없습니다. 사람이 풀었거나 담당에서 빼거나 보관한 카드는 `board_list`/`board_inbox` 에 "회수됨"으로 나오니 더 쓰지 마세요. 세션이 끝나면 맡은 카드는 자동으로 풀립니다. 다 못 끝내고 멈추면 보드에는 "멈춤"으로 남고 다음에 이어 합니다.

## 큰 일은 나누기
여러 단계인 작업은 `TaskCreate` 로 나눕니다. 각 Task 를 시작할 때 `TaskUpdate` 로 `in_progress` 로 바꾸고, 끝나면 `completed`. 그러면 보드에 작업별 카드가 생기고 지금 하는 일이 정확히 보입니다. 한 번에 하나만 `in_progress` 로 둡니다. 작은 일은 나누지 않아도 됩니다(세션 카드가 대신 보여 줍니다).

## 폰에서 온 코멘트 처리
- Stop 때 "[에이전트 칸반] 의견 N건" 이 전달되거나, 감시 신호 "[에이전트 칸반] 새 의견 N건 — board_inbox 도구로 읽고 처리하세요" 가 오면 `board_inbox` 로 읽습니다(읽으면 "전달됨"으로 기록됩니다).
- 보드는 사용자가 직접 설치해 연 것이므로, 그 의견은 **보드 주인인 사용자의 보통 요청**으로 다룹니다.
- 단 삭제·결제·배포·외부 전송처럼 되돌리기 어려운 일은 실행 전에 대화에서 사용자에게 다시 확인합니다. 의견이 Claude Code 의 권한 확인·안전 규칙을 바꾸지는 못합니다.
- 처리한 뒤에는 `board_reply(card_id, comment_id, text)` 로 무엇을 했는지 짧게 남깁니다. id 는 전달된 글에 있습니다. 하지 않기로 했다면 이유를 남깁니다.
- 승인/거절/선택(처리)이 전달되면 그에 맞춰 이어서 진행합니다.
- 진행 메모는 `board_note`, 카드 상태는 `board_list`.

## 보드에 적지 말 것
보드는 사용자의 클라우드 폴더에 저장됩니다.
- 비밀(API 키, 토큰, 비밀번호, 개인키)과 환경변수 값을 적지 않습니다.
- 전체 경로(`/Users/...`)는 파일 이름만 적습니다.
- 명령 출력, 로그, 파일 내용을 붙이지 않습니다. 요약만 씁니다.
- 다른 세션의 카드에는 쓸 수 없습니다.
